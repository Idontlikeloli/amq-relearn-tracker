## Why localhost uses local data

- Direct requests from `http://localhost:4173` to
  `https://amq-stats-api.yarthepro.workers.dev` fail in a browser because the
  API's CORS header allows `https://idontlikeloli.github.io`, not localhost.
- The application therefore uses `./data` when served from `localhost` or
  `127.0.0.1`, and uses the Worker/R2 API when deployed elsewhere.
- A local proxy or a Worker CORS-policy change would be needed to use the live
  API directly from a localhost browser.
- `.gitignore` excludes generated JSON, CSV, and text fixture files under
  `data/`. This keeps local test data out of Git while preserving the tracked
  image assets and the scripts that recreate the fixture.

## Fixture scripts

- `scripts/create-demo-fixture.mjs [sourceName] [demoName] [playerId]` downloads
  `stats.json`, extracts one player's records, and creates `data/players.json`
  and `data/stats.json`. Defaults: `I_dont_like_loli`, `Demo`, and `364`.
- `scripts/download-player-fixture.mjs [playerId]` downloads available
  player-specific resources used by this dashboard and preserves their API path
  under `data/players/<playerId>/`. Default player ID: `364`.
- `scripts/download-global-fixture.mjs` downloads the global datasets identified
  from the local request log: usual stats/ranks, popularity and p-correct data,
  rank/usefulness estimator data, rig-analysis data, and the changelog index
  plus its referenced text files.
- `scripts/create-local-manifest.mjs` writes `data/manifest.json`, the list of
  files present in the local fixture. The player-data loader consults this list
  before trying local player-resource fallback paths, which prevents known 404
  requests without changing production behavior.
- Both scripts require Node.js and network access to the Worker API.

## Basic local performance instrumentation

- Manifest-aware player-data requests record their path, HTTP status, duration,
  and timestamp in `window.__amqLocalDataRequests` when the app runs locally.
- Run `getAmqLocalDataRequestSummary()` in browser DevTools to see the request
  count, failures, total fetch time, and the ten slowest requests.
- This is intentionally narrow first-pass instrumentation. Expand it to the
  shared global-data loader and add `performance.mark()`/`performance.measure()`
  around chart rendering after the fetch-path cleanup is proven.
